# Tech stack and conventions

Monorepo: `apps/mobile` (client, web + Android), `apps/api` (server), `infra/ocr` (receipt OCR), `docker-compose.yml` (Postgres, OCR, API).

## Hard constraints
- Free resources only: Docker, open-source services, the Gemini free tier, TheMealDB, Frankfurter. No paid APIs or hosting.
- The whole stack must run in 4 GB of RAM or less. Check memory limits in `docker-compose.yml` before adding a service.
- Every feature must work on both web and Android from the same code.
- The Gemini API key lives only on the server. Never send it to, or read it from, the client.

## Client (`apps/mobile`)
- Expo SDK 57, React Native 0.86, Expo Router, NativeWind 4, Zustand.
- UI components come from React Native Reusables (the shadcn port) in `components/ui`. Don't add another component library.
- Domain logic is pure TypeScript in `lib/domain/*` and has no React imports.
- State: `lib/store/app-store.ts` holds fridge data, `lib/store/settings-store.ts` holds user preferences. Both persist to AsyncStorage through `lib/store/storage.ts`.
- When the shape of persisted data changes, bump the store's `version` and add a `migrate` step. Existing users must never lose data.
- Typecheck: `cd apps/mobile && npx tsc --noEmit`.

## Server (`apps/api`)
- Fastify 5, Zod 4, TypeScript, Vitest. Every request and AI response is validated with Zod (`src/schemas.ts`).
- Gemini is called over REST with `responseJsonSchema` generated by `geminiSchema()`. Gemini rejects `minItems`/`maxItems`, so that function strips them; Zod still enforces the limits.
- Every external call (Gemini, OCR, TheMealDB, Frankfurter) has a timeout and a fallback. The app must stay useful when AI is off or rate-limited.
- Check: `cd apps/api && npm run typecheck && npm test`.

## Style
- Pin exact dependency versions.
- Comments explain why, not what.
- User-facing text is plain, short, and never blames the user.
