Ghost Kitchen Architecture

One Expo codebase ships as an Android app and a website. Each device keeps a full offline copy of the household's food. A small self-hosted Docker stack reads receipts, asks Gemini for item names and shelf life, fetches recipes and exchange rates, and relays changes between household devices.

Decisions that shape it

Offline first

Every device keeps the whole household in AsyncStorage and works without the server. Sync is per-record last-write-wins, stamped in server time via a learned clock offset.

Server stays dumb

The API never looks inside synced data. Its own tables are caches (products, FX), an AI usage counter and household membership.

No accounts

An optional shared API_TOKEN gates the server. Household access is a per-device secret, stored as a hash.

Free to run

Three containers with hard memory limits fit a 4 GB machine. Gemini's free tier is protected by per-minute and daily caps kept in Postgres.

One web origin

The API image includes the exported Expo web build, so localhost:3000 serves both the site and its API.

CI

GitHub Actions typechecks and tests both apps, exports web, runs Playwright e2e and sprite checks, and builds both Docker images.
